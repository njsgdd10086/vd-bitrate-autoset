# vd-bitrate-autoset

Virtual Desktop 串流码率自动修改工具（GUI）。

- **三步差分定位**：用「扫描 → 改码率 → 改回」三步点击，自动找出跟随
  Virtual Desktop 码率滑块变化的真实内存地址（无需手工用 Cheat Engine 做
  Changed/Unchanged 扫描）。
- **自动指针扫描**：从定位到的地址反向解析出静态指针路径
  （如 `virtualdesktop.streamer.exe+0x2A5C8D0:0x48:0x1C`），
  与 Cheat Engine 指针扫描结果类似；候选路径需要通过多轮重启验证后才会标记为稳定。
- **自动修改**：保存路径后，每次 SteamVR 启动，自动把码率
  `10000000`(10 Mbps) 改写为 `800000000`(800 Mbps)。默认 `from` 取 10 Mbps，
  该值在 H.264+/HEVC/AV1 各编码下 VD 都能稳定设置，指针扫描结果跨编码通用。

## 编译

Visual Studio 2022（含「使用 C++ 的桌面开发」工作负载）：

```
build.bat
```

生成 `vd-bitrate-autoset.exe`（静态链接 CRT，无额外运行时依赖，
仅需 Win10/11 自带 UCRT）。程序为 64 位，
目标进程也必须是 64 位（当前 VD Streamer 为 64 位）。

## 使用流程

当前流程分为三阶段：首次建立候选、跨重启验证、开始监控。

先记住最简版：

```text
第一次：① → ② → ③ → ④ → 保存路径
第二次进程：① → ② → ③ → ⑦ 重启验证
第三次进程：① → ② → ③ → ⑦ 重启验证
最后：保存路径 → ▶ 开始监控
```

> **重要提醒：每次修改 VD 码率后，必须切换到 SteamVR 界面确认实际码率已经变化。**
> VD 设置界面的滑块变化不一定会立即同步到串流实际使用值；请先在 SteamVR 中确认新值，
> 再点击②或③。监控写入新码率后，也建议进入 SteamVR 界面确认新值已经生效。

0. 界面为深色自绘 UI，支持 125%/150% 等任意 DPI 缩放，跨显示器拖动时
   窗口、控件与字号都会自动适配（PerMonitorV2）。顶部胶囊实时显示状态：**待机中**（灰色，尚未监控）、
   **监控中**（绿色，等待 SteamVR 启动）、**休眠中**（黄色，上次修改
   完成后自动进入，需手动点「开始监控」才能恢复）。
1. 启动 Virtual Desktop Streamer，把码率滑块停在 10 Mbps
   （默认 `from`，该值对 H.264+/HEVC/AV1 编码都通用）。
2. 打开 `vd-bitrate-autoset.exe`，点击 **① 扫描码率**。
   程序会附加 `virtualdesktop.streamer.exe`，列出所有数值为
   `10000000` 的内存地址（数量通常较多，属正常）。
3. 到 VD Streamer 界面把码率滑块改为其他值（如 600），然后切换到 SteamVR 界面确认
   实际串流码率已经变成新值，等待约 1 秒后点击 **② 我已修改码率**。地址列表会收窄到「数值变化」的那些；
   结果过多时界面只展示前一部分，完整结果仍用于后续差分。
4. 再把码率滑块改回 `from`，再次切换到 SteamVR 界面确认实际码率已经恢复，点击
   **③ 我已改回码率**。
   剩下的就是真正跟随滑块变化的活地址（通常 1~3 个）。
5. 点击 **④ 查找指针路径**。程序会在后台线程反向扫描指针链，在右侧列表生成
   静态指针路径（如 `virtualdesktop.streamer.exe+0x2A5C8D0:0x48`），
   并显示每条路径当前解析到的数值。扫描期间界面保持响应，日志会逐层
   报告进度（「第 N 层: 候选指针数, 已用时」）；每个叶地址最多扫描 6 层、
   每叶限时 180 秒，默认每层最多保留 65536 个候选节点，最多 8 层；先进行 8 字节对齐扫描，
   若没有可由全部目标叶地址联合验证的路径，会自动回退到逐字节兼容扫描。
   多个编码叶地址共用同一条路径前缀、且末级偏移差与叶地址差一致的路径会优先显示；
   日志会显示命中、模块可写根、只读模块、普通内存、保留和被截断的候选数；
   路径列表最多展示前 2000 条，完整候选仍会保存并用于⑦验证，
   日志出现「④ 完成」即表示结束。若要锁定真正跨重启的指针，
   重启 VD/SteamVR 后重新完成①→③；每次改滑块后都要先在 SteamVR 界面确认实际码率，
   再点击「⑦ 重启验证」；
   连续两轮通过后，路径才会在程序重启时自动作为稳定指针使用。
6. 选中一条路径，点 **⑤ 测试路径** 验证：弹窗显示的「当前数值」
   应等于 VD 界面上当前显示的码率（10000000）。
   ④ 通常会给出多条候选（UI 缓存/编码器参数等多份拷贝），可点
   **⑥ 清除失效指针** 自动移除无法解析、或当前值既非 from 也非 to 的
   失效路径，只保留真正跟随码率滑块的路径（需 VD Streamer 已在运行）。
7. 点 **保存路径**：路径写入 `vd-bitrate-autoset.cfg`
   （默认程序同目录；若目录不可写则自动回退到
   `%APPDATA%\vd-bitrate-autoset\`），再点 **▶ 开始监控**。之后每次启动 SteamVR，
   监视器会自动按已验证路径把码率 from 改为 to，日志区会打印结果，
   托盘会弹出修改完成的通知，并自动进入休眠状态。
   未通过两轮重启验证时，只有开启「结构模式回退」才能使用结构模式回退；
   关闭该开关则必须先完成两轮验证。

辅助功能：

- **常驻托盘**：程序启动后如果已有通过验证的路径，或已保存结构模式，程序会自动开始监控。
  点击窗口右上角 × 只是把窗口隐藏到系统托盘，监控继续运行，
  下次启动 SteamVR 依然会自动修改，无需重新打开程序。
  双击托盘图标恢复窗口；托盘右键菜单「退出」才是真正结束。
- **休眠机制**：每次修改完成后自动休眠（状态变黄），避免重复写入；
  需要继续监控时再点一次「开始监控」按钮。
  可取消勾选「修改后自动休眠」：修改后不进入休眠、持续监听，
  下次 SteamVR 启动会自动再次修改（注意：持续读写进程内存，
  长时间运行可能被小蓝熊/EAC 反作弊检测，界面有警告提示）。
- **修改后弹出窗口**：勾选后，每次自动修改完成会主动把主窗口
  弹到前台（配合托盘隐藏模式使用）；不勾选则保持后台静默。
- **结构模式回退**：当保存的指针路径失效时，可自动扫描保存的连续字段布局；
  该功能可通过「结构模式回退」开关关闭。
- **重启验证**：生成候选路径后，重启 VD/SteamVR 并重新完成①→③，点击「⑦ 重启验证」；
  连续通过两轮后，路径才标记为稳定候选。
- **单实例**：程序只能运行一个实例；重复启动会自动唤起已运行的窗口
  （不会出现两个托盘图标/两套监控线程互相干扰）。
- from / to 两个输入框可自定义数值（单位为 bit）。
- 监控期间点击「保存路径」或修改 from/to 后，程序会自动重启监控线程，
  使新配置立即生效。

## 配置格式（vd-bitrate-autoset.cfg）

```
from=10000000
to=800000000
nosleep=0
popup_after=1
pattern_fallback=1
stable_rounds=0
pattern=0x0:0x4:0x8
path=virtualdesktop.streamer.exe+0x2A5C8D0:0x48:0x1C
path=...
```

`path=` 支持多行（多条路径都会被修改）。偏移数字支持 `0x` 十六进制
（含 a-f 字母时自动按十六进制解析，纯数字按十进制）。
`nosleep=1` 表示修改后不休眠（持续监听），`popup_after=1` 表示修改后
自动弹出主窗口；两个开关都默认开启（界面复选框可切换，切换即时保存）。
`pattern=` 保存多个编码字段在同一可写内存区域中的相对偏移（例如
`0x0:0x4:0x8`）。当指针路径在进程重启后失效时，监控器会重新扫描该结构；
只有找到唯一候选结构时才会自动写入，避免误改。
`pattern_fallback=0` 可关闭结构模式回退；`stable_rounds` 记录候选路径连续通过的重启验证轮数，
达到 2 轮后程序重启时才会自动优先使用这些路径。
旧配置即使没有 `pattern=`，程序也会尝试从已保存路径的连续末级偏移中自动推导
`0x0:0x4:0x8` 模式，并在下次保存时写入配置。
配置中的非法数值、开关或指针路径会被忽略并记录到日志。

也可以把 Cheat Engine 指针扫描得到的结果直接填进配置文件复用。

## 工作原理与常见问题

- 差分定位：与 CE 的「精确数值 + Changed value + Unchanged value」
  三步扫描原理相同，只是改为手动点按钮驱动。
- 指针扫描：以定位到的地址为叶节点，反向在全内存中查找 8 字节指针值
  落在「叶地址 - 64KB ~ 叶地址」范围内的指针槽，逐层向上（最多 6 层），
  直到落在某个模块映像内（模块基址 + 偏移即静态部分）。模块映像区域
  优先扫描，根指针几乎都在模块 .data 中，能更快收敛。指针按 8 字节对齐
  扫描，并对同层所有候选做单趟多目标匹配（每个内存区域每层只读一遍）。
   所有已加载模块的可写数据区中的指针槽都可以作为静态根，
  代码区和只读区命中会被排除；目标模块与其他模块根会在日志中分开统计。
  三个编码叶地址会按共用路径前缀及末级偏移关系联合评分；共用叶地址越多、
  末级偏移差与叶地址差越一致，分数越高，差值为 0/4/8 时还会额外加分。
- ② 之后列表为空：滑块数值没变（确认拖动后数值确实不同）。
- ③ 之后列表为空：滑块没有精确回到 from 的值。
- VD 滑块已经变化但②仍为空：先切换到 SteamVR 界面，确认实际串流码率已经更新；
  只有实际值变化后再点击②/③，避免只根据 VD 设置界面判断。
- ①~④ 与「⑦ 验证重启指针」都在后台线程执行，界面不会假死白屏；任务期间
  相关按钮会禁用，结束后自动恢复。日志末尾出现「完成」再继续下一步。
- ④ 之后没有路径：指针链超过 6 层、指针间距大于 64KB、候选分支超上限，
  或目标使用了更特殊的指针布局；程序会在对齐扫描无结果时自动尝试非对齐扫描，
  或扫描达到每叶 180 秒上限；可重试（VD 版本更新后建议重新定位一次）。
  曾遇到的真实案例：最后一跳偏移 49KB（> 旧 4KB 窗口）导致扫不到，
  已通过放大窗口 + 模块优先 + 逐层进度报告解决。
- 多条路径都显示正确数值：通常来自 UI 缓存/编码器参数等多份拷贝，
  全部保存即可（监视器会逐条处理）。

## 关于 VRChat / 小蓝熊(EAC)

- 本程序只读写 `virtualdesktop.streamer.exe` 的内存，从不附加、注入
  VRChat 进程，无驱动、无已知作弊工具签名，与 Afterburner/RTSS 等
  常驻工具性质相同，不会触发 EAC（EAC 只保护游戏进程）。
- 小蓝熊拦截的是 Cheat Engine 这类有签名特征的工具本身，以及对其
  保护进程的附加/注入行为，本程序两者都不沾。
- 监视器在 SteamVR 启动时只执行一次内存写入，其余时间仅每 2 秒
  查询一次进程列表，占用可忽略。需要极低存在感时可把窗口 × 掉
  （隐藏到托盘，进程仍在，监控继续）。
- 监控日志显示修改成功后，建议切换到 SteamVR 界面确认实际使用的码率已经变为 `to`；
  VD 设置界面可能不会立即反映串流端的实际值。
- 提醒：游戏期间不要开 Cheat Engine（即使不附加进程），那是另一回事。
